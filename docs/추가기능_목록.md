## 1. 장기렌트 계약서 자동 작성 → PDF

**하고 싶은 것**
장기렌트 계약서 양식을 프로그램에 넣어 두고, 계약 정보로 계약서를 자동으로 채워 PDF로 만든다.

**연결될 곳 (지금 프로그램 기준)**
- 계약 등록 화면(`ContractRegisterView`)에 이미 들어가는 정보로 계약서 칸을 채운다.
  - 고객·법인, 차량, 기간, 월 렌트료, 보증금·선납금, 인수가, 보험·정비 조건, 연체 이율·중도해지 수수료율
- PDF는 프로젝트 인쇄 규칙(`docs/print-a4-guide.md`, `printFit.js`)대로 A4에 맞춘다.
- 만든 PDF는 견적서처럼 계약자 폴더(OneDrive)에 저장한다.

**정할 것**
- 계약서 원본 양식 파일(워드·한글·PDF 중 무엇인지)과 어느 칸에 어떤 값이 들어가는지
- 약관(여러 장의 고정 문구)도 함께 넣을지
- 서명·도장: 빈칸으로 출력 / 회사 도장 이미지 넣기 / 전자서명
- 법인·개인·개인사업자별로 양식이 다른지
- 계약 수정 시 계약서를 다시 만들지, 처음 만든 것을 남길지

## 2. 핸드폰에서 볼 수 있게 (모바일 화면)

**하고 싶은 것**
밖에서도 핸드폰으로 프로그램을 열어 확인한다.

**지금 상태**
- 프로그램은 이미 인터넷 주소로 열립니다(Fly.io 도쿄 서버). 핸드폰 브라우저로 접속은 됩니다.
- 다만 화면이 PC 기준이라 표가 넓고 글씨가 작아 핸드폰에서 보기 불편합니다.

**방법**
- 새 앱을 따로 만들지 않고, 지금 화면이 핸드폰 폭에서도 보기 좋게 바뀌도록 고치는 방식이 빠르고 관리도 한 곳에서 됩니다.
- 홈 화면에 아이콘으로 추가하면 앱처럼 열리게 할 수 있습니다(앱스토어 등록 없이).

**정할 것**
- 핸드폰에서 주로 볼 화면 먼저 고르기 (예: 대시보드, 청구·입금 현황, 차량 조회, 원장 수익성)
- 핸드폰에서는 보기만 할지, 입력·수정도 할지

## 3. 핸드폰으로 클로드에게 시키면 프로그램이 처리 (AI 비서)

**하고 싶은 것**
핸드폰의 클로드 앱에 "이번 달 미입금 고객 알려 줘", "K9-001 48회차 입금 처리해 줘"처럼 말하면 프로그램에서 조회·처리한다.

**가능 여부: 가능합니다.**
- 프로그램에 클로드가 쓸 수 있는 연결 통로(MCP 서버)를 하나 만들고, claude.ai 계정에 "사용자 지정 커넥터"로 등록하면 됩니다.
- 한 번 등록하면 PC·핸드폰 클로드 앱 어디서든 같이 쓸 수 있습니다. 지금 클로드에 구글 드라이브·드롭박스가 연결된 것과 같은 방식입니다.
- 프로그램 서버에 이미 차량·계약·청구·원장 기능이 API로 나뉘어 있어서, 그 위에 통로만 얹으면 됩니다.

**처음에 할 수 있게 할 일 (예시)**
- 조회: 미입금·연체 고객, 차량 상태, 원장 정산금액·수익성, 이번 주 만기·출고 예정
- 처리: 렌트료 입금 완료 표시, 고지서 등록, 메모 남기기
- 보고: 오늘 일일 보고 요약 (AI 부서 계획의 18:30 보고와 연결)

**주의할 것**
- 로그인·권한: 대표님 계정으로만 쓰게 하고, 조회만 되는 권한과 처리까지 되는 권한을 나눕니다.
- 돈이 움직이거나 지워지는 처리(입금 처리, 삭제 등)는 클로드가 바로 하지 않고, 한 번 더 확인을 받고 실행하도록 합니다.
- 처리 기록: 누가 클로드로 무엇을 바꿨는지 활동 기록에 남깁니다.

**정할 것**
- 처음에 넣을 기능 3~5개
- 처리 기능까지 열지, 처음엔 조회만 열지

## 4. 장기렌트 ↔ 단기렌트 전환 처리

**하고 싶은 것**
- **장기 → 단기로 바꿀 때**: 그 차가 단기렌트 목록에 바로 들어가고, 단기렌트 표에서는 단기렌트 금액(일·월 대여료) 기준으로 정리된다.
- **단기 → 장기로 바꿀 때**: 렌트차량 DB 상태가 장기렌트로 바뀌고, 그 차로 장기렌트 계약서를 바로 만들 수 있다 (1번 계약서 자동 작성과 연결).

**지금 상태**
- 렌트차량 DB에 차량 상태(계약중 / 장기렌트 / 단기렌트 / 거래완료)는 있지만, 상태만 바꿔서는 다른 곳이 따라 바뀌지 않습니다.
- 차량 손익 원장의 형태(장기·단기)는 차량을 원장에 연결할 때 한 번 정해지고, 그 뒤에 차량 상태가 바뀌어도 그대로입니다.
- 단기렌트 금액(대여료) 칸은 장기렌트용 월 렌트료와 따로 있지 않습니다.

**전환할 때 함께 바뀌어야 할 것**
- 렌트차량 DB 차량 상태
- 차량 손익 원장의 형태(장기·단기)와 목록 정렬 묶음
- 장기 → 단기: 진행 중인 장기 계약과 청구 회차를 어떻게 할지 (중도해지·종료 처리)
- 단기 → 장기: 새 장기 계약 등록 → 계약서 PDF → 청구 회차표 생성
- 원장: 같은 차는 원장을 나누지 않고 한 원장에서 구간으로 이어 갈지 (지금 연장 계약을 붙이는 방식과 같게)

**정할 것**
- 단기렌트 금액 기준: 일 대여료 / 월 대여료 / 둘 다
- "단기렌트 표"가 어느 화면인지 (사고대차 정산 리스트와 같은 표인지)
- 전환 버튼을 어디에 둘지 (렌트차량 DB 수정 화면, 원장 화면 등)
- 장기 → 단기 전환 때 남은 장기 계약 처리 방법

## 5. 사고대차·단기렌트 현황 보고

**하고 싶은 것**
사고대차·단기렌트 차량이 지금 어디서 누구에게 나가 있는지, 대차·반납·정산이 얼마나 진행됐는지 한눈에 보는 보고를 프로그램에서 만든다.

**기준 양식**
실장님이 지금 쓰는 일일 보고 형식을 그대로 따른다 (제목 `이름(YYMMDD)`).
- 🔹 어제 업무: 당일 인도 완료 / 대차 진행 중 / 반납·정산 완료 건수, 청구 완료 / 입금 대기 건수
- 🔹 오늘 업무: 신규 접수 / 반납 예정, 미처리 업무, **렌터카 현황**(차종(번호 끝 4자리) : 이용자(고객 구분·대차 구분) / 현재 위치, 신규 고객 표시), A/S, 미수 대차료 정리, 영업활동
- 🔹 내일 예정: 반납 예정 / 배차 예정, 영업활동
- 🔹 비고: 특이사항, 고객 불만·CS, 공지

**프로그램이 자동으로 채울 것과 사람이 적을 것**
- 자동: 건수(인도·진행·반납·정산·청구·입금 대기), 차량별 현황(누가 타는지, 놀고 있는 차), 반납·배차 예정
- 사람 입력: 차량 현재 위치(지하전시장·철탑·3층 야외 등), 영업활동, A/S, CS·특이사항
- 자동으로 채운 뒤 실장님이 빈칸만 적고 저장·발송하는 방식

**연결될 곳**
- 사고대차 데이터: IMS(아이엠에스폼)에서 가져오는 대차 기록 (AI 부서 계획의 IMS 연동, 하루 2회 09:00·17:50)
- 단기렌트(일반): IMS에 없어서 프로그램에서 직접 입력
- 정산·미수: 보험사 청구·입금 기록
- AI 부서 계획의 **18:30 대표님 일일 보고**에 이 보고가 단기렌트·사고대차 부서 몫으로 들어간다
- 3번(핸드폰 AI 비서)과 연결하면 핸드폰에서 "오늘 사고대차 현황 알려 줘"로 볼 수 있다

**정할 것**
- 받는 방법: 프로그램 화면 / 메일 / 카카오톡·문자
- 보고 시각과 누가 작성·확인하는지 (실장님이 아침에 작성 → 대표님 확인?)
- 차량 위치를 매일 적을지, 바뀔 때만 적을지
- 일 단위 보고 외에 주간·월간 집계(가동률, 대차 매출, 미수금)도 필요한지

## 6. 대시보드 숫자 → 눌러서 보는 항목별 보고서

**하고 싶은 것**
- 통계 대시보드에는 **숫자(건수)만** 보이게 한다. 보고서 내용을 대시보드에 늘어놓지 않는다.
- 숫자를 누르면 그 항목의 **보고서**가 열린다.
  - 예: "청구 안 나간 계약 5건" → 누르면 청구가 안 나간 회사명·계약번호·차량·사유가 정리된 보고서
- 이런 보고서들이 항목별로 프로그램 뒤에서 늘 정리되어 있어서, 언제 눌러도 최신 내용이 나온다.

**지금 상태**
- 통계 대시보드에 "청구가 시작되지 않은 계약 N건"이 노란 상자로 있고, 회사 목록이 대시보드 안에 그대로 펼쳐져 있다.
- 나머지 항목(미입금, 만기 임박 등)은 건수나 목록이 화면마다 흩어져 있다.

**만들 모양**
- 대시보드: 항목별 카드 (숫자 + 짧은 이름). 0건이면 흐리게, 처리할 게 있으면 눈에 띄게.
- 보고서 화면: 카드를 누르면 열림. 표(회사명·계약·차량·금액·날짜·사유) + 해당 화면으로 바로 가기 + A4 인쇄·PDF·엑셀 받기
- 보고서마다 "언제 기준"인지 표시.

**보고서 후보 (확정 필요)**
- 청구가 안 나간 계약 (회사명 정리) ← 대표님이 예로 든 것
- 렌트료 미입금·연체
- 이번 주·이번 달 만기 예정 (인수·반납·재계약 결정 필요)
- 출고 예정·출고 준비 미완료
- 고지서(과태료·통행료) 처리 대기
- 렌트차량 DB에 없는(연결 안 된) 원장 차량
- 원장 수익성 경고 (예상 이익 마이너스, 판관비·작업비 초과)
- 사고대차·단기렌트 현황 (5번)

**연결될 곳**
- AI 부서 계획의 18:30 대표님 일일 보고는 이 보고서들의 숫자를 모아서 만들면 된다.
- 3번(핸드폰 AI 비서)이 "청구 안 나간 회사 알려 줘"에 이 보고서를 그대로 쓸 수 있다.

**정할 것**
- 대시보드에 올릴 항목과 순서
- 보고서를 지난 날짜 기준으로도 남겨 둘지(매일 저장), 늘 지금 기준만 볼지

## 7. 기존 계약서 스캔본·계약 서류 정리

**하고 싶은 것**
- 지금까지 계약한 **계약서 스캔본**을 하나씩 확인해서 내용을 프로그램에 정리한다.
- 계약서를 쓰기 전에 받는 **계약 서류**(사업자등록증, 법인등기부등본, 인감증명서, 신분증 등)도 계약별로 정리한다.

**지금 상태**
- 사업자등록증은 올리면 내용을 읽어 법인 정보에 자동 입력하는 기능이 있다.
- 사업자등록증·통장사본은 법인 관리 화면에서 올리면 문서함(OneDrive)에 저장된다.
- 계약서 스캔본은 프로그램 계약과 연결되어 있지 않고, 그 밖의 계약 서류는 받았는지 확인하는 곳이 없다.
- 계약 86건 중 상당수가 엑셀에서 옮겨 온 것이라, 계약 조건(보증금·선수금·인수가 등)이 실제 계약서와 다른 건이 있을 수 있다 (원장 보증금·선수금 오류와 같은 문제).

**하는 방법**
1. 계약서 스캔본을 모아 둔 폴더를 알려 주면, 파일마다 계약자·차량·기간·월 렌트료·보증금·선수금·인수가·특약을 읽어 표로 정리한다.
2. 그 표를 프로그램의 계약 정보와 나란히 놓고 **다른 곳만** 골라 보여 준다. 대표님이 확인한 것만 프로그램에 반영한다.
3. 스캔본 파일을 해당 계약에 연결해, 계약 화면에서 바로 열어 볼 수 있게 한다.
4. 계약마다 **받아야 할 서류 체크리스트**를 두고, 받은 것·빠진 것을 표시한다. 빠진 서류는 6번 보고서(대시보드)로 올린다.

**정할 것**
- 계약서 스캔본이 있는 폴더 위치
- 법인·개인사업자·개인별로 받는 서류 목록 (지금 실제로 받는 것 기준)

## 8. 계약 서류로 법인·개인 심사(평가) 기준 정하기

**하고 싶은 것**
계약 서류를 받으면 이 고객과 계약해도 되는지, 보증금·선수금을 얼마나 받아야 하는지를 정해진 기준으로 판단한다.

**확인이 필요한 이유**
- 지금은 심사 기준이 프로그램에 없고, 사람이 그때그때 판단한다.
- 장기렌트는 차량 값이 크고 기간이 길어, 고객이 중간에 못 내면 손실이 크다. 견적서에도 이미 "대표자 개인신용정보를 조회할 수 있다"는 안내가 들어 있다.

**확인할 것 (대표님과 정할 내용)**
- 법인: 설립 연수, 매출·영업이익(재무제표), 국세·지방세 체납 여부, 대표자 신용
- 개인사업자: 사업 기간, 소득(부가세 신고·소득금액증명), 본인 신용
- 개인: 소득 증빙, 신용 점수, 재직 여부
- 결과에 따라: 승인 / 보증금·선수금 올려서 승인 / 연대보증 / 거절
- 신용 조회를 어디서 할지 (나이스·KCB 같은 신용평가사, 캐피탈사 심사 대행 등)와 그 비용

**프로그램에 넣을 모양 (기준이 정해진 뒤)**
- 계약 서류를 올리면 심사표가 생기고, 항목별로 점수·결과를 적는다.
- 결과(승인·조건부·거절)와 근거가 고객·법인 정보에 남아, 다음 계약 때 다시 볼 수 있다.

**정할 것**
- 지금 실제로 어떻게 판단하는지 (기준이 있으면 그대로 옮기고, 없으면 같이 만든다)
- 캐피탈사(메리츠 등)에서 대출 받을 때 요구하는 심사 기준과 맞출지

## 9. 인도일에 계약사실 확인서·상환 스케줄표 자동 발송

**하고 싶은 것**
- 계약을 진행하면 고객에게 **계약사실 확인서**와 **상환(납부) 스케줄표**를 자동으로 보낸다.
- 보내는 때는 **차량 인도일 당일**이다. 인도하면서 차량을 등록하므로 그때 차량번호가 정해지고, 두 서류에 차량번호가 들어갈 수 있다.

**지금 상태**
- 차량 인도일은 렌트차량 DB(출고 준비 정보의 인도일)에 적는 칸이 있다.
- 인도일이 들어가면 청구 회차표(몇 회차를 언제 얼마 청구할지)가 만들어진다. 상환 스케줄표는 이 회차표를 그대로 쓰면 된다.
- 청구서는 이미 정해진 날 아침 9시에 메일로 자동 발송하는 기능(자동 발송 화면)이 있어서, 같은 방식으로 붙일 수 있다.
- 계약사실 확인서 양식은 아직 프로그램에 없다.

**만들 모양**
1. 차량 인도 처리(인도일 + 차량번호 입력)가 되면 두 서류를 자동으로 만든다.
   - 계약사실 확인서: 계약자(법인·대표자), 차량(차종·차량번호·차대번호), 계약 기간, 월 렌트료, 보증금·선수금, 인수가, 회사 직인
   - 상환 스케줄표: 회차 / 청구일 / 금액 / 합계, 마지막에 인수가
2. A4 PDF로 만들고 계약자 폴더(OneDrive)에 저장한다.
3. 인도일에 고객 담당자 메일로 보낸다. 보낸 기록(언제·누구에게)을 계약에 남긴다.
4. 차량번호나 메일 주소가 비어 있으면 보내지 않고, 6번 대시보드에 "발송 대기 · 사유"로 올린다.
5. 보낸 뒤 계약 조건이 바뀌면 다시 만들어 보낼 수 있게 한다.

**연결될 곳**
- 1번(계약서 자동 작성)과 같은 계약 정보·같은 PDF 방식을 쓴다.
- 4번(단기 → 장기 전환)으로 새 장기 계약이 생겨도 인도일에 똑같이 나간다.

**정할 것**
- 계약사실 확인서 양식 (지금 쓰는 양식이 있으면 받기)
- 메일로 바로 보낼지, 담당자가 한 번 확인하고 보낼지 (청구서 자동 발송은 확인 후 발송)
- 받는 사람: 계약 담당자 메일 / 대표자 / 둘 다, 카카오톡도 보낼지
- 인도일 당일 몇 시에 보낼지 (인도 처리하는 즉시 / 정해진 시각)

## 11. 중도해지 정산서 (내역·계산)

**하고 싶은 것**
계약을 중간에 끝낼 때 받을 돈·돌려줄 돈을 프로그램이 계산하고, 내역이 적힌 정산서를 만든다.

**지금 상태**
- 계약 마감은 연장·반납·인수만 있다. 반납 때 보증금 반환·손상 수리비·초과 주행은 사람이 금액을 적는다.
- 중도해지 수수료율(위약금률, 보통 30~35%)과 연체 이율은 계약·차량에 이미 저장돼 있다.
- 참고 자료: 받아 두신 "중도해지_정산서(상세).pdf"

**계산할 것 (예시 — 실제 식은 계약서 조항 기준으로 확정)**
- 남은 렌트료 × 중도해지 수수료율 = 위약금
- 미납 렌트료 + 연체이자 (연체 이율로 일할 계산)
- 사용한 달까지 일할 렌트료
- 손상 수리비, 초과 주행 정산, 과태료·통행료 미납분
- 빼는 것: 보증금, 선납금 남은 분
- 결과: 고객이 낼 돈 / 회사가 돌려줄 돈

**정할 것**
- 위약금 계산 기준 (남은 렌트료 기준인지, 차량가·잔존가 기준인지)
- 정산서 양식 (위 PDF 양식을 그대로 쓸지)

## 12. 청구서에 선수금 반영

**하고 싶은 것**
선수금(선납금)을 받은 계약은 청구서에 선수금이 계산되어 들어가게 한다.

**지금 상태 (2026-10-18 완료, 배포 대기)**
- 대표님 결정: 청구액(이미 차감된 월 렌트료)은 그대로 크게, 차감 전 월 렌트료·선납금 차감·잔액은 작게 참고로.
- 청구서 결제금액 아래 "월 렌트료 X − 선납금 차감 Y (n/N회) = 당월 렌트료 Z", 차량 표에 월 렌트료·차감·청구 렌트료 칸, 표 아래 잔액·남은 회차.
- 차감액 = 선납금 ÷ 계약 개월 수(10원 미만 버림), 끝전은 잔액에서 마지막 회차에 정리. 첫 회차 일할은 식 줄을 뺀다.
- 견적서 문구도 "월대여료는 선납금을 이미 차감한 실제 매월 납부 금액"으로 고침.
- 코드: client/src/components/admin/advancePayment.js, InvoiceSheet.jsx

## 13. 차량 원장 보기 개선 (인수인계용) — 제안 받기

**하고 싶은 것**

- 원장에 **어떤 값이 계산되어 있어야 좋은지** 정리해서 제안을 받은 뒤 고친다.

**지금 원장에 있는 것**
- 상단 정보·고정 조건, 회사출금 / 고객입금 두 열, 렌트료·보험·자동차세·검사 회차표
- 수익성 검토 (예상 이익, 보험·판관비·판매 수수료·정비 비교, 만기 반납 목표 매각가)

**제안받을 내용 (예시)**
- 맨 위 한 줄 요약: 지금 상태, 고객, 몇 회차 중 몇 회차, 다음 할 일(청구·만기·검사)
- 미리 계산해 둘 값: 남은 렌트료, 미납·연체, 다음 청구일, 만기까지 남은 달, 지금까지 손익, 예상 최종 손익
- 처음 보는 사람용 설명(이 칸이 뭔지)과 화면 순서

**정할 것**
- 제안서를 받아 보고 넣을 항목 고르기

## 15. 매월 정기점검·자동차 검사 알림

**하고 싶은 것**
매달 정기점검·자동차 검사가 돌아오는 차를 확인해서 알림으로 띄운다.

**지금 상태**
- "차량 정비·검사 관리" 화면에 차마다 다음 검사일·점검일과 "지남 / 30일 이내" 표시가 이미 있다.
- 그 화면에 들어가야 보이고, 알림으로 먼저 알려 주지는 않는다.

**만들 모양**
- 매달 1일(또는 정한 날) 그달 검사·점검 대상 차량 목록을 만들어 알림
- 대시보드(4번)에 "이번 달 검사 N대 / 점검 N대 / 지난 것 N대" 카드, 누르면 차량 목록
- 검사를 놓치면 과태료가 붙으므로 기한 지난 차는 매일 다시 알림

**정할 것**
- 알림 받는 방법 (대시보드 / 메일 / 카톡)과 받는 사람
- 며칠 전부터 알릴지 (예: 검사 30일 전, 점검 14일 전)

## 16. 계약 만료 차량 매월 보고 (만료 2개월 전부터 알림)

**하고 싶은 것**
- 계약이 끝나 가는 차를 매달 보고서로 정리한다.
- 만료 **2개월 전부터** 알림이 뜨게 해서 인수 / 반납 / 재계약(연장)을 미리 정하게 한다.

**지금 상태**
- 대시보드 서버 쪽에 만기를 달별로 묶어 보는 기능이 있다.
- 계약 연장·반납·인수 처리 기능도 이미 있다(계약 마감 창).

**만들 모양**
- 매달 보고서: 만료 2개월 이내 차량 — 고객·차량·만료일·인수가·만기 처리(미정/인수/반납)·담당자
- 만기 처리가 "미정"인 차는 계속 알림, 정하면 알림 끝
- 반납이면 원장 수익성 검토의 중고차 목표 매각가를 함께 보여 줌
- 보고서에서 바로 연장·반납·인수 처리로 이동

**정할 것**
- 보고 받는 날(매월 1일 등)과 받는 사람
- 고객에게 만료 안내를 보낼지 (2개월 전 / 1개월 전)
